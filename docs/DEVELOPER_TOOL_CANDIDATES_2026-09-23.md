# Developer tool candidates — 2026-09-23

Scope: the user's seven proposed GitHub projects were assessed as developer tools, never as automatic manuscript-processing dependencies. Current architecture already has a local Rust domain, a bounded optional ML sidecar, project-owned benchmark data, an agent next-stage protocol, GitHub CI, curated PMC notes and optional projectmem engineering memory. None is justified for installation into the product or CI at this stage. Reconsider a specific tool only against a measured unmet workflow and a pinned, reviewed version. Do not import generic agents' prompts into trusted repository instructions automatically.

| Candidate and upstream | Relevant capability | Decision and concrete reason |
| --- | --- | --- |
| [Browser Use](https://github.com/browser-use/browser-use) | Browser automation via Python/TypeScript, local or cloud browsers | Defer. Useful only if a repeatable browser-only research task is demonstrated; existing browser tooling and GitHub/API research suffice. Cloud paths have network/privacy/cost implications, and a browser must never receive an unpublished manuscript by default. Do not introduce a browser/Chromium stack into Rust runtime or CI. |
| [Agent Memory](https://github.com/rohitg00/agentmemory) | Persistent MCP memory and automatic hooks | Defer. PMC plus optional projectmem already own engineering notes. New automatic capture/hooks would add a competing memory owner and increase the chance that manuscript or private reviewer text enters developer memory. A bounded recall benchmark and explicit data-exclusion design would be prerequisites. |
| [Scientific Agent Skills](https://github.com/K-Dense-AI/scientific-agent-skills) | 166 science skills, mostly biomedical/scientific workflows | Defer. No measured English-to-Persian literary quality gap calls for installing this broad skill set; optional individual research guidance could be reviewed later, but no bulk skill install or runtime dependency. |
| [Diagram Design](https://github.com/cathrynlavery/diagram-design) | HTML/SVG editorial diagrams | Defer installation. Existing architecture docs and Mermaid/standard diagrams explain current boundaries. Adopt only for a concrete user-facing visual deliverable after reviewing the specific skill/version; generated diagrams must not become a build requirement. |
| [Anthropic Cybersecurity Skills](https://github.com/mukul975/Anthropic-Cybersecurity-Skills) | Community-made security skill collection; despite its name it explicitly states no affiliation with Anthropic | Defer. The project's CI already runs security checks; importing hundreds of dual-use prompts/scripts is disproportionate. Review one narrow defensive workflow only for a measured gap and authorized scope. |
| [Awesome Harness Engineering](https://github.com/walkinglabs/awesome-harness-engineering) | Curated reference list for context/evals/agent workflow | Reference only. A list is not installable runtime software. The repository already has a next-stage execution protocol. Revisit individual upstream links when they address a specific failure. |
| [OpenViking](https://github.com/volcengine/OpenViking) | Context database for agent resources/memory/skills, AGPLv3 upstream | Defer. Would duplicate the local memory/context owners and add service/index/network/security and licensing review obligations without measured benefit. Never replace native CharacterBible, glossary or project memory with an agent context database by default. |

Research boundaries: upstream README/docs and exact repository identity were inspected on 2026-09-23. The browser-use README distinguishes hosted cloud, CLI and Python library; Agent Memory advertises automatic hooks; Scientific Agent Skills advertises 166 skills; the cybersecurity collection says it is community-made and unaffiliated with Anthropic; OpenViking advertises AGPLv3. No package was installed, enabled, or made part of the build. Platform-specific performance and transitive vulnerability audits are deferred because no adoption is proposed. These decisions do not prevent using existing connected tools during development.
